# 竞赛程序调试

<span id="竞赛程序的编译调试与输出"></span>同一个输入能稳定重现错误时，可以在中间步骤检查变量和调用栈，找到实际状态第一次偏离预期的位置。

## 用同一个输入重现出错状态

在 Linux 上用调试符号编译，保留变量和行号。把能复现错误的最小用例存入 `input.txt`。

```bash
g++ -std=c++17 -Wall -Wextra -Wshadow -g -O0 main.cpp -o main
gdb ./main
```

在 GDB 中，`break main.cpp:42` 在第 42 行设断点（实际使用时改成目标行号），`run < input.txt` 用样例运行。执行到断点后，用 `print i` 查看本轮下标，`display a[i]` 让程序每次停住时自动显示该表达式。`next` 走过当前行，`step` 可以进入被调用的函数，`continue` 跑到下一断点。若程序崩溃，`bt` 查看调用栈，可先定位到自己写的那一层，再查参数和下标。

若问题只在处理某个输入时重现，先在[[程算 开发环境与调试|断点和单步调试]]中确认哪一步的变量最先偏离预期，再比较同一输入在本地构建和提交构建中的表现。

## 分隔符与刷新

出错的输入相同、计算状态也正确时，还要核对输出格式。行末换行和把数据送出缓冲区是两个操作，详见[[输出缓冲]]中的批量输出与交互题示例。
