# 远程项目的迁移与恢复验证

换电脑以后，克隆仓库只恢复了版本管理中记录的内容。要接着做昨天的项目，通常还需要确定依赖版本、启动方式、尚未提交的改动，以及运行期间产生的数据。迁移时先试一个能验收的小项目，问题会比搬完所有项目后再找更容易定位。

## 用一次真实任务划定边界

例如工具读入一份样例表格并输出统计报告。仓库应能提供程序、依赖声明、构建命令和可公开的测试样例。另行备份的资料要记清恢复入口；访问凭据应通过相应的凭据管理方式提供。在一个新目录从头构建，输入同一份样例，核对输出中的样本数和统计结果。如果仍要从旧电脑临时拷文件，就把缺的文件或获取步骤补进恢复说明。

| 要验证的事 | 可观察的结果 |
| --- | --- |
| 代码和依赖能够恢复 | 新目录能用记录的版本完成构建 |
| 历史工作能够接续 | 已提交版本、需要保留的未提交改动及项目数据都能找回 |
| 断开客户端不影响预期的后台任务 | 断开后重新连接，能找到同一任务及其日志、结果或失败原因 |
| 换一台客户端仍能工作 | 从另一台设备能确认工作目录、当前版本和下一步 |

## 从备份里取回一份东西

纯代码仓库可以核对提交号与构建结果。带上传文件或数据库的项目，还应分别验证程序、文件和数据之间的引用。一个小练习是在独立恢复目录中打开一条样例记录，再打开它所指的附件，看看时间、内容和关联是否相符。只看到“备份文件存在”还无法回答程序能否读取它。

交接时记下最后完成的步骤、可重新运行的验证命令、输出位置和接下来的动作。这些信息连同一次实际恢复的结果，比一张只列软件名称的环境清单更容易接手。
