# 程算 开发环境与调试

想调试一个程序，先确认正在运行的确实是自己刚改过的那一份。在 VS Code 打开项目文件夹，在终端运行 `gcc --version` 看是否找得到编译器；然后实际编译一次，核对生成的程序名和所处目录。
下面这条命令把 `main.c` 编译成名为 `main` 的程序。`-g` 保留变量和源代码行的调试信息，警告选项有助于先揪出格式串、类型或未使用变量的问题。

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic -g main.c -o main
```
如果程序能启动，结果却不对，先保留能重现问题的最小输入。循环出错就跟踪[[程算 03 流程控制|下标与不变量]]；数组或指针出错就核对对象范围和存储期；计算器则顺着分词、后缀序列和数值栈查找第一次偏离预期的位置。
断点设在想核对的那条语句上。若函数调用前的数据正确，单步越过整个调用后数据却错了，可以重新运行，这次单步进入函数，直到出错的位置。已经看清函数内部时，用跳出返回调用处。若终端一开始就报告找不到函数实现，先分清[[程算 02 C 语言基础|编译和链接]]两个阶段，再检查构建命令是否包含所需的 `.c` 文件。

课程配套《使用 VS Code 编写调试 C 程序》PDF 第 21–24 页演示编译运行，第 30–32 页演示启动调试、单步执行与断点。

## 用一个失败输入练习断点

假设计算器把 `10 - 3` 算成了 `-7`。先验证两个预期：分词后是不是数字 10、减号、数字 3；解析完是不是 `10 3 -`。若这里就错了，继续检查减法代码不会解释前一步的错误。

两处都正确时，把断点移到求值器的减法分支。弹栈前栈顶应为 3，下面是 10。第一次弹出后，调试器显示 `right = 3` 吗？第二次应得到 `left = 10`，执行 `left - right` 后结果为 7。修正后再试 `8 / 2`，它也能把左右顺序的错误暴露出来。

## 一道 iCoding 题从读题到提交

旧版《iCoding 机考系统使用说明》第 4–12 页区分了三种材料：`.md` 给题干，`.c` 给要补的程序框架，`.in` 给输入样例。先在题干里确定输入顺序和输出格式，再切到对应的 C 文件。该版说明要求将答案写在框架的 `TODO` 标记范围内。

断点设在 `scanf` 之后而调试器一直不停，先检查终端是否还在等输入。送入样例并按回车后再观察断点。若编译或链接已经失败，就回到终端看第一条错误；程序还没启动，单步调试不会到达断点。先用样例核对输出，再换一组边界输入。说明里的“已提交”只表示交卷动作已记录，不能据此推断测试通过或成绩。
