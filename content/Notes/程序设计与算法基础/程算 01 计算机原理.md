# 程算 01 计算机原理

## 存储程序与系统分层

假设一个 C 程序里有 `x = x + 1`，此刻 `x` 是 4。要让下一句读到 5，机器需要取得旧值，算出新值，再让后续指令能取到它。中间结果可以先放在 CPU 的[[二进制加法器|寄存器]]里。这里按这句代码的含义追踪，实际编译器可以合并步骤，也可以始终把值留在寄存器中。

CPU 还要知道下一步执行哪条指令。通常它取指、译码、执行，然后顺着程序往下走；碰到条件分支，就根据刚才比较的结果换一个位置继续。把指令本身也保存在存储系统里，换一组指令，同一套硬件就能从计算器变成文件复制程序。

| 层次 | 负责什么 | 编程时能看到什么 |
| --- | --- | --- |
| 硬件 | 执行指令、保存和搬运比特 | 运算、访存、输入输出 |
| 操作系统 | 管理进程、内存、文件和设备 | 程序启动、路径、权限、错误返回 |
| C 运行库 | 提供一套 C 接口封装常用操作 | `printf`、`fopen`、`malloc` |
| 应用程序 | 按问题要求组合接口与算法 | 文件复制、表达式计算 |

## 位模式要结合类型理解

试着把十进制的 `13.625` 分成整数部分与小数部分。对 13 反复除以 2，第一次得到商 6、余 1。这个余数是个位；下一次对 6 做除法，得到的余数才是二位。余数依次为 `1, 0, 1, 1`，**倒着读**得到 `1101`。

小数从另一端算。`0.625 × 2 = 1.25`，整数部分 1 给出小数点后第一位；留下 `0.25` 再乘 2 得 `0.5`，第二位是 0；最后 `0.5 × 2 = 1`，第三位是 1。**顺着读**得到 `.101`。用位权验算，$8+4+1+1/2+1/8=13.625$。十六进制里一位恰好表示四个二进制位，因此 `0xD6` 可拆成 `1101 0110₂`。

同一个四位模式 `1101`，按无符号解释是 13，按四位二进制补码解释是 −3。$n$ 位无符号数的范围是 $0$ 到 $2^n-1$，$n$ 位补码的范围是 $-2^{n-1}$ 到 $2^{n-1}-1$。补码的最高位有负权重，所以 `1101` 等于 $-8+4+1$。这也说明把数值写进某个类型之前，应先想清楚它的范围。

字符编码则是另一层映射。ASCII 给基本英文字符规定编号，Unicode 用码点标识字符，UTF-8 把码点编码成字节序列。C 的 `strlen` 对 UTF-8 统计的是 `\0` 之前的字节数。屏幕上的「汉」通常是一个字，但它的 UTF-8 编码占三个字节。

## 同一个程序运行两次，会共享变量吗？

磁盘上只有一份可执行文件，两次启动却可以同时读不同的输入。操作系统分别为两个进程维护执行位置、寄存器状态和虚拟地址空间。一个进程把自己的全局计数器从 0 改成 1，另一个进程的计数器仍可为 0。即使调试器显示两个变量的虚拟地址相同，也不能由此断定它们在访问同一份可写数据。

出处为旧课件《程序设计引论》第 35–39、47–52 页。编译、汇编、链接得到磁盘文件，装入并运行才产生进程；从第 10 章回来看这里，就能区分“缺少函数定义导致链接失败”和“可执行文件已经启动，运行中读入的数据不对”。

## 自检练习

八位 `11111111` 为什么可以表示 255，也可以在补码中表示 −1？两个答案分别依赖哪一种解释？

> [!tip]- 查看参考答案
> 无符号表示里，八位的权重从 128 到 1，全部相加得 255。补码表示里，最高位的权重改为 −128，其余七位合计 127，所以同一串比特表示 −1。
