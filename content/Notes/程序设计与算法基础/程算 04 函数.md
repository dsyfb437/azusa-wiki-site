# 程算 04 函数

## 先定契约，再写函数体

设有一个读数函数，要能读出合法的 `0`，也要在输入 `"abc"` 时报告失败。若只返回一个数字，并约好“失败就返回 0”，调用者收到 0 时就分不清这两种情况。

可以把结果分成两个出口。`int parse_number(const char *text, double *out)` 的返回值表示是否成功；成功时把数值写进 `*out`，失败时保持它原来的值。调用者提供有效的输入字符串与输出地址，只有返回 `1` 才使用新值。函数的**契约**就是把这些前提、输出和[[程算 05 变量与指针|可能修改的数据]]约定清楚。

库函数也有契约。`sqrt` 的数学定义域要求实数参数非负。`getchar` 的返回类型是 `int`，这样它既能表示读到的字节，也能表示 `EOF`。比较浮点结果若允许误差，要根据题目量纲与数值大小选容差。比较绝对差适合规模固定的数，跨数量级时还应考虑相对误差。

## 宏、函数与递归

宏直接替换文本。假设写了 `#define SQUARE(x) ((x) * (x))`，括号能保护表达式优先级，但 `SQUARE(i++)` 仍会把带副作用的表达式展开两次，产生未定义行为。需要清楚的参数类型或只求值一次时，可以用函数或 `static inline` 函数。

写递归时先确定哪些输入能直接返回，再设计每次调用怎样接近这个终止条件。调用返回后，当前层才得到子问题的结果。下面的每层都把一个十进制末位交给当前层，其余位交给下一层。

```c
#include <stdio.h>

static unsigned digit_sum(unsigned n) {
    if (n < 10) {
        return n;
    }
    return n % 10 + digit_sum(n / 10);
}

int main(void) {
    printf("%u\n", digit_sum(708));
    return 0;
}
```

把 `digit_sum(708)` 的调用和返回分开看。进入第一层时暂时只能写下 `8 + digit_sum(70)`；进入第二层，轮到 `0 + digit_sum(7)`；到 `7` 时满足 `n < 10`，可以直接交回 `7`。

现在沿原路返回。处理 `70` 的那层收到 `7`，算 `0 + 7` 交回 `7`；处理 `708` 的那层才算 `8 + 7` 得 `15`。这些尚未算完的加法就是递归过程中要保存的信息。每一层都去掉一位，层数随十进制位数增长；输入可能很深时，可以改用循环或显式栈。

## 两个看起来相近的递归，为什么耗时不同？

课程例程 `P4/P46Recursion.c` 分别递归计算阶乘和斐波那契数。计算 `f(4)` 的阶乘时，每层只有一个规模减一的新问题，返回链依次给出 1、2、6、24。斐波那契按 $F_1=F_2=1$ 定义，算 $F_5$ 既要算 $F_4$ 又要算 $F_3$，而 $F_4$ 又会重新计算一次 $F_3$。先保存相邻两项，再反复用它们的和推进一项，只需线性时间和常量额外空间。

把接口写完整时，阶乘的参数应为非负整数且结果须能用返回类型表示；上面这个斐波那契版本要求下标至少是 1，否则递归不能抵达终止条件。例程的阶乘返回 `long`，用 `printf` 核验时对应的转换符是 `%ld`。

**课件出处**　第 4 章《函数》 PDF 第 7–11 页比较几种接口设计，第 22–25 页用阶乘等例子追踪递归调用。

## 自检练习

给一个返回平方根的包装函数写接口，说明负数时怎样报告失败。

> [!tip]- 查看参考答案
> 可以约定 int sqrt_checked(double x, double *out) 接受有限实数和有效的输出地址。x 为负时返回 0，保持 *out 原值。成功时写入 sqrt(x) 并返回 1。用 x = 0、9、−1 检查零、正数和失败分支。
