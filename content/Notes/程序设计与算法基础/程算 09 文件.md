# 程算 09 文件

## 文件、路径和流

拿到 `fopen("data.bin", "rb")` 的结果，程序手里有什么？`"data.bin"` 是路径，由操作系统从进程的当前工作目录去寻找文件；成功时返回的 `FILE *` 则让 C 程序能继续从已经打开的**流**读数据。连续两次 `fgetc` 会先后读出两个字节，因为这个流记着读到了哪里。

流还保存结束、错误等状态，实际输入输出通常经过缓冲。`stdin`、`stdout`、`stderr` 是预先建立的标准流。在某些系统上，文本模式会转换换行，所以要逐字节复制一份原样数据，应选择二进制读写模式。

| 模式 | 适用情形 |
| --- | --- |
| `r` / `rb` | 读已有文件，文件缺失时失败 |
| `w` / `wb` | 写文件，成功打开时会截断已有内容，文件缺失时可新建 |
| `a` / `ab` | 追加，写入发生在当时的文件末尾 |
| 加 `+` | 增加读写能力，混合读写时遵守更新流对切换方向的要求 |

设文件只有三个字节 `00 FF 0A`。替程序预报四次 `fgetc` 的结果：前三次成功，各得整数 0、255、10，第四次才会返回 `EOF`。这时 `feof(in)` 能告诉调用者确实遇到了文件末尾；若是读错误导致的 `EOF`，要看 `ferror(in)`。

由此就能看出两个容易写错的地方。保存 `fgetc` 结果要用 `int`，以便区分有效字节与 `EOF`；先试着读，成功才处理字节。只在循环入口检查 `!feof(in)`，并不能预知下一次读取是否成功。

## 从字符复制过渡到块复制

下面按[[程算 04 函数|函数接口]]划分责任，把复制操作写成接收两个已经打开的流的函数。它处理读写失败，但流的打开和关闭仍由调用者负责。示例使用临时文件，验证含 `0x00` 和 `0xFF` 的数据能保真复制。

```c
#include <stdio.h>

static int copy_stream(FILE *in, FILE *out) {
    unsigned char block[4096];
    size_t count;
    while ((count = fread(block, 1, sizeof block, in)) != 0) {
        if (fwrite(block, 1, count, out) != count) {
            return 0;
        }
    }
    return !ferror(in);
}

int main(void) {
    const unsigned char sample[] = {0x00, 0xFF, 0x0A};
    FILE *in = tmpfile();
    FILE *out = tmpfile();
    int success = 0;
    if (in != NULL && out != NULL &&
        fwrite(sample, 1, sizeof sample, in) == sizeof sample &&
        fseek(in, 0, SEEK_SET) == 0 && copy_stream(in, out) &&
        fseek(out, 0, SEEK_SET) == 0) {
        int first = fgetc(out);
        int second = fgetc(out);
        int third = fgetc(out);
        int end = fgetc(out);
        success = first == 0 && second == 255 && third == 10 &&
                  end == EOF && !ferror(out);
    }
    if (in != NULL && fclose(in) != 0) {
        success = 0;
    }
    if (out != NULL && fclose(out) != 0) {
        success = 0;
    }
    return success ? 0 : 1;
}
```

块复制遵循同一个次序。`fread` 的每个元素大小设为 1，因此 `count` 也是这次实际读到的字节数。样例只有三个字节，缓冲区其余 4093 个位置都不该输出，所以 `fwrite` 用 `count` 作数量。若最后一块只有一半长，依旧适用。

打开输出文件前，还要确认它和输入文件独立，以免用 `wb` 截断正在读取的内容。缓冲写入的错误也可能在 `fflush` 或 `fclose` 才报告，最终的成功状态要包含关闭结果。读写格式化的文本可以用 `fprintf` 和 `fscanf`，同样需核对返回值。

## 复制了多少字节，什么时候能报告成功？

课程例程 `P91Copy.c` 依赖命令行给出源和目标两个路径，所以包含程序名在内应有三个参数。用 `rb` 读、`wb` 写，遇到 `getc` 返回 `EOF` 时退出。若输入的三个字节是 `00 FF 0A`，在成功运行且目标独立的前提下，输出也应恰好是这三个字节，复制计数为 3。

例程每读到一个字节就计数。完善时应先检查 `putc` 是否成功，再更新计数；读循环退出后检查 `ferror`，最后还要检查输出流的 `fclose`，因为缓冲写入可能直到关闭才报告失败。只有三处均无错误，才把计数作为成功复制的字节数。

## 自检练习

复制空文件、包含 `0xFF` 的文件以及读取权限不足的文件时，应该分别得到什么结果？

> [!tip]- 查看参考答案
> 空文件第一次读取就遇到流末尾，正常得到空输出。二进制模式下，0xFF 应原样写出。输入文件因权限不足而打开失败时，应先报告失败再返回，避免提前以写模式打开并截断目标文件。
